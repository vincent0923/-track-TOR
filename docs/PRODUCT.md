# 推拉机 track-TOR 产品说明

这份文档记录产品为什么存在、取舍时听谁的，以及接下来要做什么。改产品之前先读这里，方向变了也先改这里。

## 产品定位

**骑行佬练就薄肌上身的爽感健身记录 App。**

- **给谁用：** 骑行爱好者。腿和心肺已经练得不错，上半身长期闲置。
- **要达成什么：** 骑行佬本来就瘦，缺的是上身肌肉。目标是练出薄肌上身，线条好看，穿骑行服不心虚，引体越做越多。
- **靠什么坚持：** 爽感。每完成一组都有烟花和音效，进度看得见，记录本身就让人想继续。

## 设计取向

有冲突时，排在前面的优先。

1. **省事第一。** 操作越少越好，授权越少越好，一次授权管得越久越好。
2. **爽感是核心功能，不是装饰。** 烟花、音效和进度条要保留并继续打磨，别为了“简洁”砍掉。
3. **围绕上身力量和引体。** 新功能先问：它能帮用户多练、练得更爽吗？不能就先不做。
4. **一天的练习都放在那一天。** 同一天的正式动作和加练记在同一个面板里，方便统一管理。
5. **图表只算连续、可信的数据。** 断档的日子不凑数，宁可显示“–”。
6. **数据留在用户手机里。** 没有账号，也没有我们的服务器。备份是用户自己手里的一个文件。
7. **零门槛分享。** 把网址发给别人就能用，不用安装，不用注册。
8. **界面能用图标说清就不写字。** 操作就放在它影响的内容旁边，比如在图表上直接记录，不单独开一个表单。

### 关于安全的态度

健身和饮食数据不算敏感信息。这里的用户要的是省事，不是层层防护，所以：

- 高驰授权长期保存在手机里，到期前自动续期。
- 备份文件带上高驰授权，换手机恢复后不用重新授权。
- 如果真要在省事和谨慎之间取舍，默认选省事，并如实告诉用户影响。

只有可能直接造成真实损失的事才例外，比如泄露财务信息。真出现这类功能，要单独讨论。

## 现在的样子

| 模块 | 做法 |
|---|---|
| 形态 | 单文件网页 `index.html`，可装到手机主屏，部署在 GitHub Pages |
| 数据 | 存在浏览器 `localStorage`，用 txt 进度文件备份和恢复 |
| 训练 | 20 天推拉计划，共 40 次训练，逐级解锁；每个训练日都有加练区，默认引体向上 |
| 饮食 | 在数据页填总热量和蛋白质、脂肪、碳水、蔬菜（总热量必填），填齐蛋白质、脂肪、碳水后可一键估算总热量来核对，也能逐项记明细，结合高驰活动数据算热量缺口 |
| 图表 | 趋势图在数据页；引体、体重和腰围点手写图标记录，日期默认当天 |
| 高驰 | 浏览器直连，支持中国大陆、欧洲和美国区；一次授权，自动续期 |
| 语言 | 中文和英文 |

**授权能撑多久：** access token 约 30 天，refresh token 约 180 天。网页在剩余不足 15 天时自动续期，所以约半年内打开过一次，就不用重新授权。同一份授权恢复到两台设备上时，一台续期后另一台可能要重新授权一次。

- [ ] **新用户引导：** 代码里默认的生日、身高和目标都是开发者本人的，要改成让用户自己填，否则基础代谢和目标对别人都不准。
- [ ] **中国实测：** 还没有在中国实际打开过网页，也没有用中国区账号完整登录过。

### 让使用更省事

- [ ] 打开网页时自动同步高驰，不用手动点。
- [ ] 进度自动备份，尽量不用用户记着做。
- [ ] 中国访问提速：去掉 Google Fonts 外链，网络慢时优先用离线缓存打开。

- [ ] 休息日也能方便地记加练。现在休息日没有自己的面板，只能记在别的训练日里。
